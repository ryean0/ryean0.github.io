CI Agent Regression Harness

Three answers. Never a shrug.

Every suite ends in one of these. There is no silent pass, and no per-scenario gate.

  1. No regressionThe new agent holds up on the same scenarios.
  2. Likely regressionIt got worse, and the 90% interval agrees.
  3. Invalid runThe data is not good enough to say either way.

Spec sheet

The bar, written down.

These are decision rules, not a customer scoreboard. A One full try of one scenario. Pass scores 1. Fail scores 0. is one try. A pass is 1. A fail is 0. The verdict is for the suite, not for each task.

90%

Confidence level. A regression is called only when the whole interval sits below zero.

1 or 0

Every usable rollout is a pass or a fail. No partial credit.

Paired

Outcomes are matched by scenario. Order does not matter. Each scenario is a diagnostic, not its own gate.

5%

Miss ceiling. More than 5% of scheduled runs missing or broken by infrastructure, on either arm, and there is no verdict. Exactly 5% still scores.

60% up

Each scenario needs at least ceil(0.6 × scheduled) usable runs on both arms. 5 needs 3. 7 needs 5. 20 needs 12.

Hashed

Every scenario is content-hashed. A stale or edited test invalidates the run instead of changing the score.

How it works

Same tasks. Both versions. One call.

The harness sits in CI, between “the change looks fine” and “merge it.”

  1. 01

    Lock the scenarios

    Write the tasks that matter. Each one is sealed with a content hash, so a stale or edited test cannot quietly move the score.

  2. 02

    Run both versions

    The CI job runs every scenario on the baseline and on the candidate. Repeats are normal: twenty times on the current agent, five on the new one.

  3. 03

    Score the rollouts

    Pass is 1. Fail is 0. If the candidate hangs because it is looping, or because it blew its step budget, that timeout is a fail.

  4. 04

    Set infrastructure aside

    A provider outage, a rate limit, or a killed runner is not the agent’s fault. Those runs are excluded. If they pile up past 5% on either side, there is no verdict.

  5. 05

    Publish one answer

    The scorer pairs the outcomes by scenario and reports a likely regression only at 90% confidence. Otherwise it says no regression, or invalid run. That answer is for the suite.

Why you can trust the call

It would rather say nothing than say the wrong thing.

Fair comparison

Outcomes are paired by scenario. A difficult refund and an easy password reset do not get stirred into one average that hides the miss. The order of the list does not change the answer.

candidate rate − baseline rate, then an unweighted mean

Honest about hangs

If the candidate times out because it is looping or it spent its step budget, that counts as a fail. Timeouts from infrastructure — provider 5xx, rate limits, a CI runner killed — are excluded instead.

agent timeout → score 0 · infra timeout → set aside

Refuses bad data

If more than 5% of scheduled rollouts on either arm are missing or broken by infrastructure, the run is invalid. Exactly 5% is fine. Each scenario also needs a floor of usable runs on both arms.

5 → 3 usable · 7 → 5 · 20 → 12 · 6% on one arm → no verdict

Tamper-evident scenarios

Each test is content-hashed. If the text in the results does not match the suite, the run is invalid. Stale tests and quiet edits get caught before they become a score.

SHA-256 of the scenario text, checked before the verdict

FAQ

Plain answers.

What does the harness decide?

Whether a new version of an agent got worse than the one you already run, before you ship it. The answer is one suite-level call, not a pass or a block on each scenario.

What is a rollout?

One try at one scenario. Pass scores 1. Fail scores 0. The harness repeats the scenario because a single try can be lucky.

Why can the candidate have fewer runs?

Twenty baseline runs against five candidate runs is a normal plan. Each scenario becomes a pass rate, then each scenario counts once toward the suite. Extra runs do not buy an extra vote.

What does 90% confidence mean?

A likely regression is called only when the entire 90% confidence interval for the pass-rate gap sits below zero. If the interval still includes “no real change,” the harness does not call a regression.

When does it refuse a verdict?

If more than 5% of scheduled runs on either side are missing or broken by infrastructure. Exactly 5% is still scored. And each scenario needs at least 60% of its scheduled runs usable, rounded up: 5 needs 3, 7 needs 5, 20 needs 12.

Does a timeout count as a failure?

If the agent was looping or it used up its step budget, yes. If the timeout was infrastructure — a provider error, a rate limit, or the CI runner being killed — that run is set aside.

Are the numbers on this page customer results?

No. The results panel shows the bundled preliminary example file. The simulator uses labeled sample data. Neither is a customer benchmark.
