CI Agent Regression Harness

Catch agent regressions before they ship.

Specification

The decision rules.

A One execution of one scenario. A pass scores 1. A fail scores 0. is one execution. Pass is 1. Fail is 0. The status applies to the suite.

90%

Confidence level. A regression is called only when the full interval lies below zero.

1 / 0

Every usable rollout is a pass or a fail. There is no partial credit.

Paired

Outcomes are matched by scenario. Order does not change the result. A scenario is a diagnostic, not a gate.

5%

Miss cap. Above 5% missing or infrastructure-broken on either arm, the run is invalid. Exactly 5% still scores.

60%

Coverage floor. Each scenario needs at least ceil(0.6 × scheduled) usable rollouts on both arms. 5 needs 3. 20 needs 12.

SHA-256

Scenarios are content-hashed. A stale or edited test invalidates the run.

Method

Same scenarios. Both versions. One check.

The job runs in CI, after the change is built and before it merges.

  1. 01

    Lock the scenarios

    Define the tasks that matter. Each one is sealed with a content hash, so an edited test cannot move the score.

  2. 02

    Run both arms

    The same suite runs on the baseline and the candidate. A typical budget is 20 rollouts on the current agent and 5 on the candidate.

  3. 03

    Score rollouts

    Pass is 1. Fail is 0. A step-budget or loop timeout on the agent is a fail.

  4. 04

    Exclude infrastructure

    Provider 5xx, rate limits, and a killed runner are not the agent’s score. If those misses exceed 5% on either arm, there is no verdict.

  5. 05

    Publish the suite status

    Paired by scenario, at 90% confidence: pass, likely regression, or invalid run.

Gate behavior

No verdict when the run cannot support one.

Paired comparison

Each scenario contributes one difference: candidate pass rate minus baseline pass rate. Those differences are averaged without weights. List order does not change the result.

unweighted mean of per-scenario gaps

Timeout policy

A loop or an exhausted step budget scores 0 and stays in the sample. Provider 5xx, rate limits, and a killed CI runner are excluded from the score and counted toward the miss cap.

agent timeout → 0 · infrastructure timeout → excluded

Validity

More than 5% of scheduled rollouts missing or infrastructure-broken, on either arm, invalidates the run. Exactly 5% remains valid. Each scenario also has a coverage floor on both arms.

5 → 3 usable · 7 → 5 · 20 → 12 · 6% on one arm → invalid

Content hashes

Each scenario is hashed. If the recorded text does not match the suite, the run is invalid before a score is published.

FAQ

Operational questions.

What does the harness decide?

Whether a candidate agent regressed relative to the one already running, before the change ships. The output is one suite status, not a pass or a block on each scenario.

What is a rollout?

One execution of one scenario. Pass scores 1. Fail scores 0. Scenarios are repeated because a single execution is not a stable estimate.

Why does the candidate have fewer rollouts?

Twenty baseline rollouts against five candidate rollouts is a normal budget. Each scenario becomes a pass rate, then each scenario counts once. Additional rollouts do not add weight.

What does 90% confidence mean here?

A likely regression is reported only when the entire 90% interval for the pass-rate gap lies below zero. If the interval still includes no change, the harness does not call a regression.

When is a run invalid?

When more than 5% of scheduled rollouts on either arm are missing or broken by infrastructure. Exactly 5% is still scored. Each scenario also needs at least 60% of its scheduled rollouts usable, rounded up: 5 needs 3, 7 needs 5, 20 needs 12.

Does a timeout count as a failure?

A loop or an exhausted step budget scores 0. A provider error, a rate limit, or a killed CI runner is excluded and counts toward the 5% miss cap.

Are the figures on this page customer results?

No. The results panel shows the bundled preliminary file. The console replays labeled sample configurations. Neither is a customer benchmark.
